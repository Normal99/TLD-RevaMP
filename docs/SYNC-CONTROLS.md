# Car controls and part removal

The 2026-10-19 client marks show Car06P owned by player 1 with ignition and engine running, while its momentary key stays at 0. That key value is not the ignition flag or engine state. The host's marks are unavailable, so these captures cannot establish exactly what its screen displayed.

Only the car owner runs ignition logic. A proxy still forwards key holds through message 96 and passenger input through message 39, then displays the owner's ignition and engine state. The ignition is projected before the game calculates `localIgnition`; an older reliable car record cannot replace a received ignition signal. Engine bindings belong to the car entity: registering or releasing a proxy part attached to that car must not replace or remove its engine binding.

Detached parts remain in their original group's item list. Edits now prefer the part's own entity, then an unsplit group membership. This matters for Radio01: the radio mark contains 21 full usable edits addressed to Car06P member 21, which had already become entity 432. Live usable validation now resolves that part's prefab from its original group when it has no standalone record. Reach and live relay interest follow its current attachment parent. Reliable usable records raise tune and switch events only when those values change, so tuning, volume zero and AM/FM reach the radio's consumer as live updates do.

The corrected headlight symptom is that the **frame owner cannot remove its headlights**, while another player can. Removal uses the part's entity ownership rather than proxy status inherited from its frame's transform root. A locally owned part runs the game's `UnCraft` and `Detach`, then broadcasts `DetachSync` (an existing entity) or `PartOff` (an unsplit group member). A proxy part on a locally owned frame still requests removal from the part's owner. Nested members use their current group. The owner handler runs the same full unbolt outside the local player's update scope; receivers unbolt under `_applyingDetach`, without an outgoing request or detach echo. These paths are in `Entities.Removal.cs`, extracted without changing their behavior so the unit project exercises the production hooks and receiver.

One remaining owner-path failure was the `ServerDetachReq` early return when the requester already owned the entity on the server. An ownership change can overtake a request made while the local part was still a proxy: its local unbolt was suppressed, but the server silently discarded the request. Validated requests now go to the current owner even when that is the requester. Reach and rate checks still apply; ownership is unchanged. `detach-request` and `detach-refused` events record the address and refusal reason. The single-machine headlight mark does not establish that this race caused the original playtest symptom. The steady owner path already uses part authority in 094830b; the added tests cover that path explicitly. State/resync receivers reject non-proxy entities and skip split members; physics-lock code refuses to store attached items and releases a stale lock without unbolting the part.

The wheel mark has all four Car06P wheel slots occupied: RR entity 151, FR 443, RL 436 and FL original member 10. Its event window contains no attach/detach sequence that identifies the visual error. No wheel placement change is inferred from this evidence. Loaded occupied slots now capture `mountPosCm`, `mountRot` and `crafted`, taken from the part's mounting transform. Compare the same slot on both machines after crafting has settled: a nonzero mounting position or differing rotation exposes a misplaced wheel even when both slot lists agree. Stored slots omit these live-only fields.

Local marks include a slug made from the privacy-cleaned note, using ASCII letters, digits and hyphens, with a path-budgeted length up to 500 characters (`unknown` when empty). Received names budget their slug for the player index and eight hash digits appended as a suffix. Transfer metadata still carries the existing note-free basename, separate cleaned note and full SHA256; deduplication uses the full hash. Protocol.Version is 44: every Claim is six bytes (message, net id and diagnostic producer byte), and held transitions use ordinary State flags. World-pose physlocks retain their mount address for takeover without a viewer scan (43); 42 added the producer byte to every Claim; protocol 40 added the stable UTC session date, mark origin and rename synchronization; 41 added the host-authenticated renamer index to rename relays. Older protocols are refused during the handshake. The comparer discovers captures by content and extension, independent of the note or hash suffix.

Offline coverage is in `SyncControlsTest`, the report transfer/sharing/privacy tests, telemetry serialization tests and the comparer tests. The removal tests cover local and remote frame ownership crossed with headlight ownership by the host, local player, frame owner and a third player; full unbolting and detach replay on the peer; unsplit nested members; and ownership overtaking a pending request. Unity objects and the game's mechanical unbolt are faked. A two-machine test must confirm short and long key holds (owner, passenger and outside user), engine state after taking an attached part, radio tune/on/off/AM-FM on both owned and proxy radios, and headlight removal with different frame ownership. Reproduce the wheel error with marks from both machines to compare mounting transforms.
